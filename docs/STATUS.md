# 진행 상태 (PHASE 1 기준)

작성일: 2026-11-05

지시서 14장의 PHASE 1(실행 가능한 핵심 MVP)을 구현했습니다. PHASE 2~5는 시작하지 않았습니다(일부 항목은 PHASE 1에 필요해 먼저 넣었습니다).

## 1. 실제로 동작을 확인한 것

| 항목 | 확인 방법 |
| --- | --- |
| 중앙 서버, 로그인, 조직 격리 | 서버 자동 테스트 16건 |
| 프로젝트 생성 → 작업 대기열 → PC 배정 | 서버 테스트 + E2E |
| PC 등록(일회용 연결 코드), PC 상태·AI 로그인 상태 표시 | E2E, 브라우저 확인 |
| 작업 임대·heartbeat·임대 만료 회수·엔진 재시작 복구 | E2E "장애 복구" (엔진 프로세스 강제 종료) |
| 기획 결과(TASKS.json)를 의존성 있는 개발 작업으로 분할 | 서버 테스트 + E2E |
| Git 작업 폴더, 작업별 체크포인트 커밋, 실제 변경 파일 수집 | 엔진 테스트 + E2E |
| 실제 명령 실행으로 검증(`npm test`, `npm run build` 등) | E2E (종료 코드·로그 기록 확인) |
| 검증 실패 → 실패 로그를 담은 수정 작업 → 재검증, 3회 한도 | E2E 2개 시나리오 |
| AI가 "완료"라고 해도 산출물·변경이 없으면 실패 처리 | 서버 테스트 + E2E |
| 소스 ZIP 생성, SHA-256 기록·대조, 웹 다운로드 | E2E (내려받은 ZIP을 풀어 다시 테스트 실행) |
| 실시간 로그(WebSocket), 순번 보장, 중복 제거 | 서버 테스트 + E2E |
| 수동 승인 모드, 최종 결과 승인, 실행 중 취소 | E2E |
| 웹 화면(PC·휴대폰 크기) | 실제 브라우저로 전체 흐름 조작 |
| Codex CLI 설치·로그인 상태 감지 | 실제 Codex CLI 0.166.0 으로 확인 |

## 2. 만들었지만 실제 환경에서 확인하지 못한 것

정직하게 구분해 둡니다. 아래는 코드는 있으나 이 개발 환경(클라우드 Linux)에서는 끝까지 검증할 수 없었습니다.

| 항목 | 이유 | 확인 방법 |
| --- | --- | --- |
| **실제 Codex로 코드 생성** | Codex는 사용자 본인의 ChatGPT 계정 로그인이 필요합니다. 어댑터는 공식 `codex exec --json` 명령 규칙에 맞춘 대역 프로그램으로만 검증했습니다. | PC에서 `codex login` 후 작은 프로젝트를 요청 |
| **Windows에서의 엔진 동작** | Linux에서만 실행했습니다. Windows용 분기(프로세스 종료, `.cmd` 실행)는 작성만 했습니다. | Windows PC에서 `scripts\install-engine.ps1` |
| **Codex 샌드박스의 Windows 동작** | `--sandbox workspace-write` 가 Windows에서 기대대로 동작하는지 미확인 | 첫 실행 로그 확인 |
| Windows 트레이 앱·설치 패키지(Electron, NSIS) | Windows와 Electron이 없어 실행·빌드 불가 | `apps/engine/desktop` 에서 `npm install && npm run dist` |
| Android APK/AAB | Android SDK 없음. PWA 설치는 가능 | `android/README.md` |
| Docker Compose 실행 | 이 환경에 Docker 데몬이 없음. Dockerfile의 빌드 단계는 같은 명령으로 재현해 확인 | `docker compose up -d --build` |

## 3. 지시서와 다르게 한 것

| 지시서 | 실제 구현 | 이유 |
| --- | --- | --- |
| Tauri(Rust) | Electron + Node.js | 시작 전 사용자가 선택 |
| Redis + BullMQ | PostgreSQL 기반 대기열(`FOR UPDATE SKIP LOCKED` + 임대) | 작업을 가져가는 쪽이 원격 PC라서 DB 임대 방식이 더 단순하고, 서버 재시작에도 상태가 남습니다. 별도 유료 Redis가 필요 없습니다. |
| S3 호환 스토리지 | 서버 디스크(볼륨) | PHASE 1 범위. 저장 경로 계산이 한곳에 모여 있어 교체 가능 |
| PC↔서버 WebSocket | PC가 서버로 보내는 HTTPS 요청(폴링) | 방화벽·프록시 환경에서 안정적. PC는 포트를 열지 않습니다. 웹 화면의 실시간 표시는 WebSocket입니다. |

## 4. 아직 없는 것 (남은 작업)

**PHASE 1 범위 안에서 빠진 것**
- 참고 파일 업로드(PDF·Excel·이미지), 기존 소스·Git 저장소 연결. 지금은 글과 참고 URL(문자열)만 받습니다.
- 요구사항이 불명확할 때 사용자에게 되묻기. 지금은 AI가 가정을 세워 `docs/REQUIREMENTS.md` 의 "확인 필요 사항"에 적습니다.
- 웹의 파일 탐색기·코드 보기·Git diff·이전 버전 복원. 소스는 ZIP으로만 받습니다.
- 반자동 모드와 자동 모드의 차이. 위험 작업(배포 등)이 아직 없어 현재는 동일하게 동작합니다.
- 검증 명령의 컨테이너 격리. **AI가 만든 테스트 코드가 PC 사용자 계정 권한으로 실행됩니다.** ([보안·운영 가이드](SECURITY_OPERATIONS.md) 2장)
- 위험 명령(관리자 권한·방화벽 등)의 EUM 자체 승인 절차. 지금은 Codex 샌드박스와 지시문 규칙에만 의존합니다.
- 프로젝트는 처음 배정된 PC 한 대에 묶입니다. 그 PC가 꺼져 있으면 대기합니다.
- 엔진 토큰은 명령줄 모드에서 사용자 폴더의 설정 파일에 저장됩니다(트레이 앱은 Windows 보안 저장소로 암호화).
